# Developer bugs: QuixBugs (Python) — 2026-11-07

**Result: 9 of 40 real developer bugs repaired (22.5%), all 9 correct, 0
rollback violations, 0 edits to a test.** This is the first measurement on bugs
written by people. The seeded-fault benchmark
([second pass](SEEDED-HELDOUT-v2-2026-11-06.md)) measures single-token faults
in Rust; this one measures the same deterministic engine, with no LLM, no
network and the same 64-candidate budget, on 40 classic Python algorithms that
each carry one developer-written bug.

Raw table: [`repair-quixbugs-2026-11-07.md`](repair-quixbugs-2026-11-07.md).

## Setup

- **Corpus.** [QuixBugs](https://github.com/jkoppel/QuixBugs) (Lin, Koppel et
  al., MIT licence) at commit `4257f44`, imported with
  `scripts/import_quixbugs.py`. Each fixture holds the buggy program, its pytest
  test and JSON vectors, and QuixBugs' `conftest.py`. The correct programs are
  not in the fixture tree, and the test's `--correct` import branch is removed.
- **Oracle.** QuixBugs' own tests. Every file except the program is pinned, so
  editing a test scores OVERFIT.
- **Held out.** None of the engine's operators or ordering rules were tuned on
  QuixBugs. The changes made while setting this run up only stop a hanging test
  from hanging or aborting `axiom solve`, plus one safety rule. They are listed
  below, and none of them adds a repair.
- **Run.** `AXIOM_SOLVE_VERIFY_TIMEOUT_SECS=5` per candidate (a QuixBugs test
  takes well under a second when it terminates) and
  `AXIOM_BENCH_VERIFY_TIMEOUT_SECS=60` for the runner's own baseline and
  post-solve runs. The 40 fixtures ran in four chunks of ten so a container
  restart could not lose the whole run. Wall time was 2–7 minutes per fixture,
  about 80 minutes in total.

## The nine repairs

Each accepted edit was compared with QuixBugs' `correct_python_programs/`:

| program | accepted edit | vs the reference fix |
|---|---|---|
| `find_first_in_sorted` | `while lo <= hi` → `<` | identical |
| `gcd` | `gcd(a % b, b)` → `gcd(b, a % b)` | identical |
| `knapsack` | `weight < j` → `<=` | identical |
| `next_palindrome` | `len(digit_list) * [0]` → `(len(digit_list) - 1) * [0]` | identical |
| `next_permutation` | `perm[j] < perm[i]` → `>` | identical |
| `rpn_eval` | `op(token, a, b)` → `op(token, b, a)` | identical |
| `sieve` | `any(n % p > 0 …)` → `all(…)` | identical |
| `levenshtein` | `1 + levenshtein(…)` → `1 * levenshtein(…)` | equivalent: the reference drops the `1 +` |
| `quicksort` | lesser `x < pivot` → `x <= pivot` | equivalent: equal elements go left instead of right, same sorted output |

`sieve` is repaired by the `any`↔`all` operator added for the seeded benchmark.
That is the one QuixBugs repair that operator work contributed.

## Why the other 31 were not repaired

The fix each one needs, from a diff against the reference program:

| fix shape | n | examples |
|---|---|---|
| a missing statement | 4 | `nodesvisited.add(node)`, `prevnode = node`, `opstack.append(token)`, `lines.append(text)` |
| one name replaced by a different name (one-sided) | 5 | `enumerate(arr)` → `enumerate(counts)`, `(start, helper)` → `(start, end)`, `outgoing_nodes` → `incoming_nodes` |
| ±1 on a variable (not a literal or `len()`) | 3 | `binsearch(mid, end)` → `mid + 1`, `range(0, r)` → `range(0, r + 1)`, `dp[i - 1, j]` → `dp[i - 1, j - 1]` |
| operand or subscript order | 2 | `result + alphabet[i]` → `alphabet[i] + result`, `[j, k]` → `[k, j]` |
| bitwise operator | 1 | `n ^= n - 1` → `n &= n - 1` |
| wrap in a call, add a condition, or change an expression | 16 | `max(0, x)`, `or not coins`, `return True` → `return depth == 0`, `[]` → `[[]]`, `approx` → `approx ** 2` |

None of these is in the engine's single-edit operator family. That is the
honest gap between seeded single-token faults (39/40) and developer bugs
(9/40). Three families would be cheap and general next operators: ±1 on a
variable, swapping a binary operator's operands or a subscript's elements, and
bitwise operator swaps. Together they cover 6 of the 31. One-sided identifier
substitution covers 5 more, but it multiplies the candidate count. The
remaining 20 need edits that insert code (statements, conditions, calls),
which is beyond a single-token mutator and is what the LLM phase (Phase 3) is
for.

**Once any of these operators exists, a QuixBugs re-run is in-sample.** A
held-out claim after that needs a different developer-bug set.

## Repair-loop fixes this run required

QuixBugs `bitcount` never terminates (`n ^= n - 1`), and that exposed three
ways a hanging test hung or aborted `axiom solve`. All three are fixed:

1. The supervisor's first run of the verify command had no time limit, so
   `axiom solve` never returned. It is now bounded by the verify timeout
   (`axiom run`, which may supervise a server, is unchanged).
2. A test timeout inside the Poly-JIT phase returned an error that aborted the
   whole solve. It now means "this phase did not fix it", and the solve moves
   on to mutation repair.
3. A killed test prints no `file:line`, so localization found nothing. It now
   falls back to the files the verify command names and follows a test's
   imports to the code under test. Helpers that sit beside the test (QuixBugs'
   `load_testdata.py`) rank after the program.

The benchmark runner's own baseline and post-solve runs are bounded too
(`AXIOM_BENCH_VERIFY_TIMEOUT_SECS`).

One safety rule was added after a first pass. On `depth_first_search` the
mutation search went green by swapping two node names in the **test's** graph
setup. The runner caught it as OVERFIT, but the engine should never make that
edit: a blind single-token change to the oracle can only weaken it. Mutation
repair now never edits a test file, and that is the configuration measured
here. The agentic eval still scores 32/32.

## Reproduce

```bash
git clone https://github.com/jkoppel/QuixBugs /tmp/QuixBugs   # 4257f44
python3 scripts/import_quixbugs.py --src /tmp/QuixBugs --out /tmp/repair-quixbugs
AXIOM_SOLVE_VERIFY_TIMEOUT_SECS=5 AXIOM_REPAIR_CORPUS=/tmp/repair-quixbugs scripts/bench_repair.sh
```

Running the corpus executes QuixBugs' test code, which is third-party code:
run it where that is acceptable.
