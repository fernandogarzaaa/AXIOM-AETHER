# Held-out repair rate on seeded faults, regenerated suite — 2026-11-11

**Result: 19 of 36 seeded faults repaired (52.8%), 0 rollback
violations.** Deterministic, CPU-only, no LLM, no network. This is the
re-baseline for the Phase 4 unseen suite after regeneration (Codex P1,
PR #294): the 18 fixtures that shared a (file, line, class) triple
with the repair-seeded-mesh-core tuning tables were replaced at fresh
sites (batch 3, seed 424244). The shipped 36 now share zero triples
with any tuning table, so the headline 19/36 IS the fresh-site rate;
there is no tuned subset left to flatter it.

Raw table: [`repair-unseen-seed424242-36-regen-2026-11-11.md`](repair-unseen-seed424242-36-regen-2026-11-11.md).
Pre-regeneration baseline (19/36 with the overlap, tuned 18 repaired
12, fresh 18 repaired 7): [`UNSEEN-SEED424242-2026-11-10.md`](UNSEEN-SEED424242-2026-11-10.md).

## Setup

- **Corpus.** `bench/corpus/unseen-seed424242/` (36 fixtures: 18
  retained from batches 1-2 plus 18 batch-3 fixtures at fresh sites;
  77 faults attempted, 23 survived the kill filter). Every
  `meta.json` verify command resolves its shared target directory from
  the runtime environment
  (`CARGO_TARGET_DIR="${TMPDIR:-$HOME/.cache}/axiom_seeded_target"`),
  so no committed fixture carries a machine-specific path.
- **Oracle.** The crate's own `cargo test --lib`, with the test region
  pinned (any edit at or below the `#[cfg(test)]` line scores OVERFIT).
- **Run.** `scripts/bench_repair.sh` with
  `AXIOM_REPAIR_CORPUS=bench/corpus/unseen-seed424242`,
  `AXIOM_BENCH_LABEL=unseen-seed424242-36-regen`,
  `AXIOM_SOLVE_VERIFY_TIMEOUT_SECS=30`, candidate cap 64, release
  `axiom` 0.7.0 built from this branch. `TMPDIR` was unset, so the
  portable verify resolved to `$HOME/.cache/axiom_seeded_target`
  and built it cold (278M) on the first fixture. Slowest fixture
  98.7s (`mesh-L351-deref-30`).

The operator set's blind spots are total: `deref`, `cast`, `ret`,
`shift` repair 0/14 combined, exactly as designed (no operator adds
`&`/`*`, rewrites a cast target, or flips a shift; `ret` is inside
the set via MissingReturn yet repairs 0/4 here, all four being
compile-error faults whose type ascription the operator cannot
recover). The strengths are equally clear: `arith`, `idswap`,
`offbyone`, `const`, `neg` repair 17/19.

## Correct, not just test-passing: 16/19 authored, 3 different

16 of the 19 accepted edits are the exact seeded reversal ("authored
fix"). The 3 "different fix" edits were re-run with the release
solver and diffed against the seeded reversal by hand:

- `mesh-L214-offbyone-14`: the fault is `self.nodes.len() + 1 !=
  before` (should be `!=` without the `+ 1`); the solver instead
  changed the comparison to `self.nodes.len() + 1 == before`.
  Equivalent under the crate's unique-`NodeId` usage (`retain` can
  remove at most one node with a given id, so "length changed" and
  "length dropped by exactly one" coincide). Not identical in the
  duplicate-id corner, which the code does not forbid; no caller or
  test duplicates an id.
- `mesh-L394-neg-07`: `!(self.nodes.is_empty())` became
  `(self.nodes.is_empty())`, the authored fix plus redundant parens.
  Identical. (Verified in the 2026-11-10 write-up; same fixture, same
  accepted edit, reproduced in this run.)
- `mesh-L199-offbyone-07`: the fault is `node.affinity.len() + 1 !=
  self.config.dim`; the solver changed the comparison to
  `node.affinity.len() + 1 == self.config.dim`. **Not equivalent.**
  It rejects exactly when `len == dim - 1` and admits a node with
  `len == dim + 1`, which the correct guard rejects. It passes the
  oracle only because the suite never adds a node with `len == dim +
  1`. It counts as PASS under the harness (the oracle is the test
  suite), and is recorded here as a test-passing non-equivalent fix,
  not as a correct repair.

## The seventeen misses

No single pattern dominates beyond the class table above: all 5
`deref`, all 4 `cast`, all 4 `ret`, and the 1 `shift` miss (the
operator set has no move for them), plus 1 `idswap`, 1 `arith`, and 1
`cmp` miss. `deref`/`cast`/`ret` faults mostly fail to compile (8 of
the 18 batch-3 fixtures are compile-error faults); the solver's
candidates are source edits judged by a compile-and-test oracle, so a
fault that needs a type-level repair is out of reach of the current
operator set by construction.
