# Held-out repair rate on seeded faults, seed 424242 — 2026-11-10

**Result: 17 of 24 seeded faults repaired (70.8%), 0 rollback
violations.** Deterministic, CPU-only, no LLM, no network. This is the
baseline for the Phase 4 unseen suite: the faults come from a different
seed (424242) and a revised generator (new `strlit` class) than the
seed-2026/seed-7 corpora, and no operator or ordering rule was tuned
against them.

Raw table: [`repair-unseen-seed424242-2026-11-10-2026-11-09.md`](repair-unseen-seed424242-2026-11-10-2026-11-09.md).

## Setup

- **Corpus.** `bench/corpus/unseen-seed424242/` (24 fixtures, class-
  balanced by `scripts/seed_faults.py --seed 424242 --balance --n 24`).
  33 faults were attempted, 9 survived the kill filter (the crate's own
  suite does not catch them) and were excluded. The `strlit` class added
  for this generator revision contributed 0 faults: `axiom_mesh_core`
  has exactly 1 `strlit` candidate site and the suite does not catch it.
- **Oracle.** The crate's own `cargo test --lib`, with the test region
  pinned (any edit at or below the `#[cfg(test)]` line scores OVERFIT).
- **Run.** `scripts/bench_repair.sh` with
  `AXIOM_REPAIR_CORPUS=bench/corpus/unseen-seed424242`,
  `AXIOM_SOLVE_VERIFY_TIMEOUT_SECS=30`, candidate cap 64. Total wall
  time about 15 minutes; the slowest fixture took 140 s.
- **Invalid first run, discarded.** The first baseline attempt scored
  0/24 because `cargo` was not on the runner's `PATH`: every verify
  failed with exit 127 ("cargo: not found") and every solve stopped
  after one attempt with the diagnosis "missing executable `cargo`".
  That 0/24 is an environment failure, not a repair result; it was
  discarded and the run repeated with `~/.cargo/bin` on `PATH`. The
  invalid run's results file was overwritten by the valid re-run.

## Correct, not just test-passing: 17/24

14 of the 17 accepted edits are the exact seeded reversal ("authored
fix"). The other 3 ("different fix") were re-run with
`AXIOM_BENCH_KEEP=1` and their accepted edits diffed against the seeded
reversal by hand; all three are semantically equivalent to it:

- `gumbel-L26-range-18`: the fault is `(0..=n)` in `sample_gumbel`
  (should be `(0..n)`); the solver instead changed the caller to
  `sample_gumbel(logits.len() - 1, rng)`, which yields the same sample
  count (and the draws are iid, so the same distribution). Equivalent
  at the call site, but it leaves the faulty range in place for any
  future caller.
- `mesh-L276-range-09`: `0..=logits.len()` became
  `0..=logits.len() - 1`, which iterates exactly `0..logits.len()`.
  Identical.
- `mesh-L394-neg-07`: `!(self.nodes.is_empty())` became
  `(self.nodes.is_empty())`, the authored fix plus redundant parens.
  Identical.

Unlike the seed-7 write-up, there is no strengthened test suite for
this seed yet to re-run the equivalent fixes against; equivalence was
judged by reading the three diffs. Writing that strengthened suite is
a qualification-run follow-up.

## The seven misses

No single pattern dominates: one shift fault, one identifier swap, one
argument swap, one logic fault, one min/max fault, and two arithmetic
faults. Each is a case where the repair loop either did not rank the
fault site first or exhausted its 64-candidate budget without a
verifying edit. These are the concrete next targets for operator work,
but per the suite's exclusion rule no operator work was done on the
basis of this run.
