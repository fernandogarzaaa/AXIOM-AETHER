# Axiom Phase 2.0.1 — Contrastive Bidirectional Embedder (Design)

**Date:** 2026-06-06
**Status:** Approved design — pending implementation plan
**Author:** Brainstormed with Claude (Opus 4.8)
**Depends on:** Phase 2.0 (memory store + recall + eval harness), see `2026-06-06-phase2-persistent-memory-design.md`

---

## One-line

A self-contained bidirectional transformer encoder, trained from scratch with
InfoNCE on mined + synthetic pairs, producing semantically discriminative `[d]`
embeddings so memory recall (cosine over the JSONL store) returns the right
memory — gated by the `eval_recall` precision@k harness built in 2.0.

---

## Why this (the 2.0 finding)

Phase 2.0 shipped the memory plumbing but `eval_recall` exposed the blocker: the
production d256 TTT LM's hidden states are **collapsed** as embeddings —
mean inter-query cosine **0.93**, inter-seed **0.95**, residual similarities do
not track semantics, precision@3 only 0.40 (mean-pool) / 0.60 (last-token, and
that 0.60 is artifactual — the ranking was query-independent). Mean-centering /
anisotropy correction did nothing. A 256-dim / 4-layer / ~90k-token **causal**
LM has no retrievable semantic structure, and no pooling trick or frozen linear
head recovers signal that is not there.

**Locked decision:** train a dedicated contrastive embedder as Axiom's own
self-contained artifact — NOT an imported third-party model (would break the
single-binary property and outsource the moat), NOT a head on the frozen
backbone (backbone is collapsed).

---

## Locked decisions (from brainstorming, 2026-06-06)

| Decision | Choice |
|---|---|
| **Positive pairs** | **Hybrid**: mined NL↔content pairs (docstring/comment↔body, markdown heading↔section) **+** synthetic queries generated by Claude through the running proxy |
| **Corpus** | **Both**: the user's own local repos (domain match) **+** a broad multi-language crawl (volume, diversity, hard negatives) |
| **Architecture** | **Purpose-built bidirectional transformer encoder**, mean-pool, trained from scratch with InfoNCE → separate `axiom_embedder.bin` (production d256 untouched) |
| **Pooling** | **Mean-pool** over token outputs (textbook sentence-embedding default) |
| **GPU logistics** | Restart proxy with `AXIOM_DEVICE=cpu` (co-tenancy guard) so it stays up on CPU; train encoder on the full GPU; restore proxy to GPU after |

## Architecture — the encoder (`src/encoder.rs`, new)

A standard **bidirectional** transformer encoder — genuinely different from
`AxiomTTTLM` (causal/recurrent TTT):

```
input_ids [B, T]
  → token Embedding + learned positional embedding         [B, T, d]
  → N × EncoderBlock:
        multi-head self-attention (NO causal mask)          [B, T, d]
        + residual + LayerNorm
        FFN (d → ffn → d, GELU)                              [B, T, d]
        + residual + LayerNorm
  → mean-pool over T (mask-aware: ignore pad positions)     [B, d]
  → L2-normalize                                            [B, d]
```

- Reuses the 16k ByteLevel BPE tokenizer (`checkpoints/axiom_bpe.json`).
- **Starting config (sized for the 6 GB RTX 2060):** `d_model=384, n_layers=6,
  n_heads=6, ffn_dim=1536, max_seq=256`. Tunable; the plan will allow env
  overrides like the existing trainers.
- Attention implemented directly with candle primitives (q/k/v `Linear`
  projections, scaled dot-product `softmax(QKᵀ/√d_head)V`, no mask), since the
  TTT code has no attention to reuse.
- Persisted as `axiom_embedder.bin` (safetensors via VarMap) +
  `axiom_embedder.meta.json` (d_model, n_layers, n_heads, ffn_dim, max_seq,
  vocab, pooling="mean", eval precision@k).

## Data pipeline (`src/pairs.rs` + `bin/build_pairs.rs`, new)

1. **Crawl** the user's repos + a broad multi-language corpus via the existing
   `corpus_crawl` / `corpus.rs` utilities → text shards under `checkpoints/corpus`.
2. **Mine NL↔content pairs** (label-free), one `{anchor, positive}` per match:
   - **docstring / leading-comment ↔ following declaration body** — per language:
     `///` and `/** */` (Rust), `"""..."""` (Python), `/** */` and `//` runs
     (JS/TS/Go/Java/C/C++/C#).
   - **markdown heading ↔ its section body**.
   - (Commit-message ↔ diff is explicitly **deferred** — needs git plumbing; not
     in this phase. See Out of scope.)
3. **Synthetic queries:** for a bounded sample of content chunks, call Claude via
   the running proxy (`POST http://127.0.0.1:3000/v1/messages`, passthrough OAuth)
   to generate a natural-language question whose answer is that chunk →
   `{anchor: question, positive: chunk}`. Bounded by a configurable count to cap
   cost/time.
4. Output append-only `pairs.jsonl` (`{anchor, positive, source}` where `source`
   ∈ `doc|md|synthetic`). **Negatives are in-batch** (every other positive in the
   training batch) — no explicit negative mining needed for v1.

## Contrastive training (`src/contrastive.rs` + `bin/train_embedder.rs`, new)

Mirrors `bin/train_semantic.rs`: a 1 GiB-stack thread, AdamW, global grad-norm
clip, linear LR warmup, `VarMap::save`, `meta.json` sidecar, env-configurable
hyperparameters, OOM-resilient steps.

- **InfoNCE loss:** for a batch of `B` pairs, encode anchors `A[B,d]` and
  positives `P[B,d]` (both L2-normalized). Similarity matrix `S = A·Pᵀ / τ`
  `[B,B]`. Cross-entropy with target = diagonal index (row i's positive is column
  i; all other columns are in-batch negatives). Symmetric: average the
  anchor→positive and positive→anchor losses. Temperature `τ` env-configurable
  (default 0.05).
- Train/val split on pairs; early-stop on val InfoNCE.
- **Device:** `cuda_if_available` (GPU), with the proxy first moved to CPU so the
  6 GB is free.

---

## Integration (`src/embedder.rs` + `src/mcp_stdio.rs`, modify)

- New `EmbeddingModel` struct: owns the loaded encoder + tokenizer; method
  `embed(text) -> Vec<f32>` (tokenize → bidirectional forward → mean-pool →
  L2-normalize).
- `embed_text`: **if `axiom_embedder.bin` + sidecar exist → construct/use
  `EmbeddingModel`; else fall back to the Phase-2.0 TTT pooling
  (`pool_last_normalize` over `forward_hidden`).** 2.0's plumbing keeps working
  and upgrades transparently the moment the artifact appears.
- `McpContext` gains an `Option<Arc<EmbeddingModel>>` loaded at boot when the
  artifact is present; `remember`/`recall` workers use it (falling back to the
  pipeline embedder when absent).

---

## Error handling — fail-open preserved

- Missing or corrupt `axiom_embedder.bin` → fall back to TTT pooling (2.0
  behavior). Recall never breaks; the proxy is never worse than 2.0.
- Training is a separate binary — never relinks or touches the running proxy
  `.exe` (CPU-only `cargo test --lib` discipline from 2.0 continues for unit
  tests; the trainer is its own `--release --bin`).
- Synthetic-query generation unavailable (proxy/Claude down) → skip synthetic
  pairs, train on mined pairs only (graceful degrade; logged).

## Testing & acceptance gate

**Unit tests (CPU, `cargo test --lib`):**
- encoder forward shape `[B,T]→[B,d]`; output is finite and unit-norm; two
  *different* inputs produce *different* embeddings (anti-collapse guard).
- attention has no causal mask (a later token influences an earlier token's
  output — assert position 0's output changes when a later token changes).
- InfoNCE: identical anchor/positive batch → loss near `ln(1)`≈0 at τ→0 when the
  diagonal dominates; gradient is finite; loss decreases on a 2-step overfit of a
  tiny batch.
- pair-mining: a Rust `///`-doc + fn yields one `{anchor=doc, positive=body}`;
  markdown heading+section yields a pair; non-matching text yields none.
- `EmbeddingModel` fallback: absent artifact → `embed_text` uses TTT path.

**Acceptance gate (`eval_recall`, already built):**
- **precision@3 ≥ 0.80** AND **mean inter-query cosine < 0.60** (proof embeddings
  vary by input — directly refutes the 0.93 collapse).
- A held-out pair-retrieval metric (recall@1 over held-out mined pairs) tracked
  during training as the early-stop signal.

## Phasing (cheap-first — de-risk the architecture before the big run)

- **2.0.1a — encoder + InfoNCE + tiny smoke train (AXIOM-AETHER only, CPU-ok).**
  Prove the *pipeline* produces discriminative embeddings: after a short train on
  this repo's own doc↔body pairs, `eval_recall`'s inter-query cosine must drop
  well below 0.93 and precision must rise above the 2.0 baseline. This validates
  the architecture + loss before any large crawl or GPU run. Lowest cost.
- **2.0.1b — full data + full GPU run.** Crawl user repos + broad corpus, mine
  pairs, generate synthetic queries, train on GPU (proxy on CPU) → produce
  `axiom_embedder.bin` that clears the acceptance gate.
- **2.0.1c — integration.** Wire `EmbeddingModel` into `embed_text` + `McpContext`
  (with fallback), re-run `eval_recall` through the real recall path, confirm the
  gate holds end-to-end.

> The ordering is the risk management: 2.0.1a proves the bidirectional-encoder +
> InfoNCE recipe works *at all* on a trivial corpus before committing crawl/GPU
> time to 2.0.1b.

---

## Out of scope (YAGNI for 2.0.1)

- Commit-message ↔ diff mining (needs git plumbing; add later if recall needs it).
- Explicit hard-negative mining (in-batch negatives first; add mined hard
  negatives only if the gate isn't cleared).
- ANN index (brute-force cosine still fine at personal scale, per 2.0).
- Replacing the proxy's d256 LM (compression/drift) — the embedder is a separate
  artifact; the LM is untouched.
- Phase 2.1 (salience ingest) / 2.2 (silent injection) — still gated on this
  embedder clearing recall.

---

## Success criteria

1. `eval_recall`: **precision@3 ≥ 0.80** and **mean inter-query cosine < 0.60**
   with the trained `axiom_embedder.bin`.
2. The encoder is self-contained: loaded by the same binary, no external model or
   network dependency at inference.
3. Fail-open intact: with the artifact absent/corrupt, recall behaves exactly as
   Phase 2.0.
4. The production d256 LM (compression/drift) is byte-unchanged.
