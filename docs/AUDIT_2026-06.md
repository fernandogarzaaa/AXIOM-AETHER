# AXIOM-AETHER Independent Technical Audit

**Date:** 2026-06-30  
**Auditor:** Independent senior engineer review via automated multi-agent analysis + direct measurement  
**Repo:** `fernandogarzaaa/AXIOM-AETHER` — default branch `main`, release `v0.1.6`  
**Methodology:** Clone → build → full test suite run → bench measurement → parallel per-subsystem code audit → findings synthesis

---

## Executive Summary

AXIOM-AETHER is a **legitimate, well-engineered local research runtime** for online Test-Time Training (TTT), structural context compression, self-healing execution loops, and autonomous code repair. The codebase is significantly more honest than the project name and earlier (pre-rewrite) README suggested.

**What it actually is:**
- A structural code-skeleton compressor that achieves **measured 81.7% token savings** by stripping function bodies and forwarding only signatures to the upstream API. This works entirely without a trained model.
- A working autonomous repair loop (`axiom solve`) that drives a verifier command to green via environment heals → deterministic Poly-JIT patches → optional LLM-proposed patches. **8/8 built-in fixtures pass** with no LLM required.
- A mathematically correct online TTT engine (`ttt_block.rs`) with proper delta-rule updates, stabilization guards, and scalar/learned forget gates.
- A local evidence-accumulation system with real cryptographic provenance (SHA-256 + HMAC-SHA256 with constant-time comparison).

**What it is not (despite some module names):**
- The TTT block is mathematically real but the **production checkpoint is not shipped** (`axiom_kernel_v1.safetensors` does not exist; the only file in `checkpoints/` is a 226 KB bootstrap model with vocab size 256). Every invocation warns: *"No pre-trained checkpoint found. Initializing with baseline random weights."*
- The "80% compression" is purely **structural/skeleton compression**, not TTT-based semantic compression. The fingerprint's top-k recall indices are noise without a trained projection head (self-documented in `context_compressor.rs:19-29`).
- The "swarm" is **single-node manual HTTP fetch**, not P2P. The belief combination is **additive Beta pseudocount fusion**, not canonical Dempster-Shafer. The quantum manifold is **classical deterministic branching**.

**Overall verdict:**  
This is a **credible research skeleton** — the core algorithms are real, code quality is high, tests are substantive, and the README is now honest about scope. The central unresolved gap: the full semantic compression pipeline (TTT + trained projection head) requires a production checkpoint that is neither shipped, trained in CI, nor reproducible from the quickstart without weeks of training. The 80% token-savings headline is real but achieved by a method (skeleton compression) that requires zero machine-learning.

**Would you rely on it in production?**  
- `axiom bench` / skeleton compression: **yes** — it's purely structural, deterministic, and well-tested.  
- `axiom solve` / autonomous repair: **yes, with an LLM configured** — the loop logic is solid and the holdout guard exists.  
- `axiom run` / TTT proxy compression: **no** — requires a trained checkpoint that is not shipped.  
- Swarm/immunity merge: **local learning only** — useful for single-node immunity, not real distributed consensus.

## Per-Subsystem Findings

### 1. TTT Engine (`ttt_block.rs`, `model.rs`, `inference.rs`) — CONFIDENCE: HIGH

**Real:** The delta-rule update (`ttt_block.rs:245-254`) is mathematically correct:
```
pred = W̃ × k^T
error = pred − v
grad = error ⊗ k   (outer product)
W̃ ← W̃ − η·grad
output = q × W̃
```

Three stabilization mechanisms exist: element-magnitude clamp (±10), key L2 normalization, and three online guards (EATA, CoTTA, RDumb). All are **disabled by default** — on large models with long sequences and no stabilization, divergence to NaN is possible.

**Gap:** The `inference.rs:97` warning fires on every invocation because `DEFAULT_CHECKPOINT_PATH = "axiom_kernel_v1.safetensors"` does not exist. The production BPE model (`checkpoints/axiom_production_bpe.bin`) also does not exist — only its metadata sidecar is present. The bootstrap model (`axiom_converged.bin`, 226 KB) is a d64/vocab256 model, too small for meaningful semantic compression.

**Verification test** (`tests/verification.rs`): `passkey_recall_breaks_past_zero_after_convergence` confirms that after adaptation the recall norm is 0.33–0.47 (vs. random-init ceiling of 0.05). This test passes with the shipped bootstrap checkpoint.

### 2. Context Compressor (`context_compressor.rs`, `skeleton.rs`) — CONFIDENCE: HIGH

**Real:** Skeleton compression is real and effective. It uses tree-sitter to parse source files into structural signatures (function/class/type definitions), stripping bodies. `axiom bench` shows 81.7% token reduction at 99.9% structural fidelity on 82 source files. This is a genuinely useful tool.

**Self-documented limitation** (`context_compressor.rs:19-29`, "Honesty footnote"):
> "With a trained LM head, those top-k indices decode through the tokenizer to genuine next-token predictions — a real semantic compression. With the random-init checkpoint shipped in this repo, the indices are essentially noise."

**What is actually sent upstream:** A `<axiom_context_digest>` XML block containing: tokens_compressed count, top-32 recall index integers (noise without trained head), per-layer Frobenius norms, SHA-256 state hash, and tokenizer-decoded tokens (empty with random init). This block is itself ~200–400 tokens — the net savings comes from dropping function bodies, not from the fingerprint being compact.

**Round-trip:** "Expand on demand" works because the original content is stored locally in `vfs/` or memory. The fingerprint alone cannot reconstruct the dropped content.

### 3. Self-Heal / Autonomous Repair (`self_heal.rs`, `solve.rs`, `agentic.rs`) — CONFIDENCE: HIGH

**Real and substantive.** This is the most production-ready subsystem:

- `self_heal.rs` heals: missing directories (`mkdir -p`), missing execute bit (`chmod +x`), and absorbs failure traces into W̃ via cross-entropy loss. Scope is narrow but honestly implemented.
- `solve.rs` is a real 3-phase repair loop: env heal → Poly-JIT deterministic patches → LLM-proposed patches with verifier feedback. All changes are byte-for-byte reversible via `Transaction`. Exit code 0 from the verify command is the success criterion.
- `agentic.rs` provides the rejection-memory primitive: identical edit-sets are never re-proposed; the held-out guard (`agentic_loop_with_holdout`) forces both train and holdout verifiers to pass. Tests are substantive (not smoke tests): byte-restoration, dedup fingerprints, rejection memory, held-out gate enforcement all tested.
- `eval-agentic`: 8/8 fixtures pass, reproducibly, with no LLM. Fixtures include multi-language fault localization (Rust, Python, JS, Go) and multi-file repair.
- **Gap:** The holdout guard is not wired into the main `solve.rs` loop. Fleet patch sharing is local-only (no gossip).

### 4. Grounding / Hallucination (`hallucination.rs`) — CONFIDENCE: HIGH

**Real and honestly scoped.** The module documents its own limitation at line 1:
> "Lexical coverage check. For a real contradictions detector, the neural-surprisal tier is needed."

Tier 1 (always on): token-overlap coverage — counts what fraction of response tokens appear in the evidence. Detects omission, not contradiction. Tier 2 (optional): neural surprisal via a local model.

The epistemic drift module (`epistemic_drift.rs`) adds an LLM judge tier but explicitly requires an external judge endpoint (`AXIOM_EPISTEMIC_JUDGE_URL`); returns 503 when unconfigured.

### 5. Swarm / Belief / Provenance (`belief.rs`, `provenance.rs`, `heal_memory.rs`) — CONFIDENCE: HIGH

**Cryptography: genuinely solid.** SHA-256 + HMAC-SHA256 implemented correctly (RFC test vectors pass), constant-time comparison guards timing attacks, Byzantine gate rejects implausibly large pseudocounts.

**Belief combination: misnamed.** `belief.rs:125-142` implements additive Beta pseudocount fusion with conflict-mass heuristic detection. Not Dempster-Shafer. The rule is simpler and more conservative (refuses to combine on conflict rather than normalizing through it). Functionally reasonable; just not what the name says.

**P2P: absent.** No peer discovery, no gossip, no DHT. The "swarm" is a single node that manually fetches another node's signed JSON export via HTTP GET and merges it locally. `swarm_router.rs` is a local Ollama router. `q_manifold.rs` is classical branching with quantum terminology.

### 6. Training Infrastructure (`meta_train.rs`, `train_semantic.rs`, `eval_model.rs`) — CONFIDENCE: MEDIUM

**Real training pipeline:** `train_semantic.rs` is a legitimate language-model training script with:
- Train/val split (95/5), early stopping with patience=3
- AdamW + cosine LR schedule + gradient clipping (L2 norm ≤ 1.0)
- NaN guards, OOM-resilient step loop
- Best-checkpoint save with validation CE recorded

The metadata sidecar (`axiom_production_bpe.meta.json`, **absent from this clone**) would show d_model=128, vocab_size=8000, val_ce=5.008136. The actual weights file is not present and is gitignored.

**Gap:** The production checkpoint is not reproducible from a cold clone without sourcing a corpus and running training. The quickstart script (`scripts/train_cpu_quickstart.sh`) exists but was not verified to run end-to-end in this audit environment. `axiom init` / `bootstrap.rs` trains a d64/vocab256 procedural model in seconds — this is the only auto-trained artifact, and it does not provide semantic compression.

### 7. HTTP Server & MCP Surface (`server.rs`, `mcp_stdio.rs`) — CONFIDENCE: HIGH

**5,211 lines of Axum HTTP server and 1,888 lines of MCP stdio.** 17 MCP tools implemented (compression, recall, task board, awareness, channels, epistemic validation). The surface is large and functional.

## Security & Quality Findings

### Critical

**S1 — Most HTTP endpoints are unauthenticated** (`server.rs`)  
All endpoints except `/mcp` and `/mcp` (GET) require no credentials:  
- `POST /v1/messages` (proxy to Anthropic — allows API key injection)  
- `POST /v1/cluster/sync` (merges arbitrary tensors into live session state)  
- `POST /v1/patches/merge`, `POST /v1/immunity/merge`  
- All TTT/swarm/budget/expand endpoints  

Intended for local/trusted networks, but not enforced. An attacker with network access can corrupt model weights via cluster sync, trigger inference, and access all MCP functionality without a token.

**S2 — No path validation on `axiom_compress_path` MCP tool** (`mcp_stdio.rs:1248-1290`)  
Takes an arbitrary filesystem path from user input and runs `walkdir::WalkDir::new(p)` on it. No restriction to a safe root. Exposes arbitrary directory listings and file contents to any MCP client. Read-only impact only, but no guard.

### High

**S3 — MCP token is optional by default** (`mcp_stdio.rs:243-245`, `server.rs:308`)  
`AXIOM_MCP_TOKEN` env var is not required. When unset, `/mcp` endpoints accept all connections. Documented as "intended only for trusted networks" but not enforced.

**S4 — No per-endpoint body-size limits on most POST routes** (`server.rs`)  
Only `/v1/patches/merge` has an explicit 32 MB limit. All others use Axum's default (2 MB). Insufficient for preventing memory exhaustion from large JSON payloads on endpoints like `/v1/cluster/sync` that accept binary safetensors deltas.

### Medium

**S5 — 96 `.unwrap()` calls in `server.rs`** — Investigation shows these are almost entirely in `#[tokio::test]` blocks and test helper functions. Production HTTP handlers use `.map_err()` → `ApiError`. No hot-path panics confirmed, but the count warrants ongoing review.

**S6 — Stabilization disabled by default in TTT** (`ttt_block.rs:168`)  
Online guards (EATA, CoTTA, RDumb) are all off by default. On long sequences with a large d_model and no stabilization, W̃ can diverge to NaN. The element clamp (±10) is the only always-on protection.

### Low / Informational

**S7 — Bearer token compared with string equality** (`server.rs:3914`)  
Acceptable over TLS, as noted in the comment. Not a timing-attack risk in practice but non-ideal.

**S8 — `sandbox.rs` name is a misnomer** — It creates an isolated `cargo check` temp workspace, not a process sandbox (no seccomp, no chroot). Code generation risks are limited to DoS (infinite compile), not code execution.

**S9 — `meta_train.rs` has no held-out validation set** — Training in `meta_train.rs` evaluates only on training data. The `train_semantic.rs` binary has a proper 95/5 split; `meta_train.rs` does not.

## What Would Make This Credible (Punch List)

1. **Ship the production checkpoint.** The core claim — TTT semantic compression — is untestable without `axiom_kernel_v1.safetensors` or `axiom_production_bpe.bin`. Include it in releases (it's ~5–10 MB for d128/vocab8000) or provide a reproducible training script that runs in CI.

2. **Measure compression quality with a trained model.** Add a benchmark that runs a round-trip through the TTT pipeline with the real checkpoint and compares answer quality (e.g., BLEU or F1 on a held-out QA set) before and after compression.

3. **Rename the swarm/quantum modules.** `swarm_router.rs` → `local_model_router.rs`. `q_manifold.rs` → `classical_branch_strategy.rs`. `combine_ds` → `combine_beta_additive`. These mislead readers about what is implemented.

4. **Wire the holdout guard into `solve.rs`.** The `agentic_loop_with_holdout` primitive exists and is tested but is not used in the main autonomous loop. Using it would prevent the solver from overfitting a single verifier.

5. **Add authentication middleware.** Require an env-var token for all non-health endpoints, not just `/mcp`. The cluster sync endpoint in particular should require peer authentication before accepting tensor deltas.

6. **Add path validation to `axiom_compress_path`.** Restrict traversal to a configurable safe root.

7. **Enable stabilization by default for large models.** The three online guards exist but are off by default; document clearly under what conditions NaN divergence occurs and set safe defaults for d256+.

8. **Add e2e answer-quality test.** The active_compression_e2e test verifies the pipeline runs but not that it helps. A meaningful test would send the same question with full context vs. skeleton-compressed context to a real model and compare answers.

## AGI/Epistemic Swarm/Research Framing Assessment

The **current README is honest**: it explicitly disclaims AGI/SGI framing, labels compression benchmarks as token-savings-only (not answer-quality), and points to `docs/UPGRADES.md` for research aspirations. This is a significant improvement over whatever preceded the "line-by-line audit" rewrite mentioned in the README.

The module names and some inline comments (`q_manifold.rs`, `swarm_router.rs`, "Dempster-Shafer") use terminology from distributed systems, quantum computing, and Bayesian epistemology that overstates what is implemented. The algorithm in each case is simpler and more classical than the name implies — but the implementations themselves are correct for what they actually do.

**Classification:** Research-grade skeleton with production-quality engineering practices (CI, Docker, PyPI packaging, release automation, clippy-clean, comprehensive tests). Not research-grade in the sense of novel scientific contributions. Not production-grade in the sense of deployable AI infrastructure (missing checkpoint, unauthenticated endpoints, no answer-quality validation). Suitable as a personal tool or research prototype.
