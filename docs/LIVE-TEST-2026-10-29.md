# AXIOM-AETHER — Live test (2026-10-29)

A deep live test of the shipped surfaces using the **release binary built from
this tree** (`axiom 0.5.0` plus the unreleased changes on PR #246) and the
**published checkpoints from Hugging Face**, on a 4-core CPU-only Linux host.
Nothing here is a unit test: every number comes from running the real binary,
scripts, and servers. No upstream LLM key was available, so every proxied call
went to a local mock upstream; the one thing this test cannot say is anything
about answer quality.

## Results

### 1. Checkpoint loading and compression (`axiom bench axiom_engine_rs/src`, 138 files)

| Checkpoint | Load | Token savings | Round-trip |
|---|---|---|---|
| optimfix (multilang main) | full load, no warnings | **86.3%** (707,594 → 96,733) | 2897/2897 = 100% |
| baseline v6.18 | **partial load**: 14 tensors the checkpoint predates (`fast_bias`, `w_lr`, `lr_scale`, `surprise.*`, `learnable_token_idx` ×2 blocks) filled by init fallbacks, as #222 intends; warning printed | 86.3% | 2897/2897 |
| v0.4.1 | same partial load, same 14 tensors | 86.3% | 2897/2897 |
| legacy 256-vocab (no checkpoint) | | 83.7% (233,945 → 38,150) | 2897/2897 |

The identical savings across checkpoints are expected: signature extraction is
structural and model-independent (RESULTS.md says so); the percentage depends
on the tokenizer, not the weights. Sidecars without `schema_version` load as
schema 0 without complaint, as designed.

### 2. First-run journey (`scripts/new_user_simulation.sh`, fresh `HOME`)

7/7 steps pass. `axiom init` **downloaded the real optimfix checkpoint from
Hugging Face** (8.6 MB, SHA-256 printed with "unverified — no expected hash
configured"), scaffolded `~/.axiom`, then meta-trained and bootstrapped the
small offline `axiom_kernel_v1.safetensors`. Self-heal created a missing
directory and the command succeeded on retry; `axiom immunity` reported the
learned heal with a Beta confidence; `axiom eval-agentic` scored 14/14.

### 3. End-to-end demo (`scripts/demo_end_to_end.sh`)

## Findings

1. **`axiom init` downloads the production checkpoint but does not use it.**
   The optimfix file lands in `~/.axiom/models/`, but the production path
   (`AXIOM_PRODUCTION_BPE=1` + `AXIOM_TOKENIZER` + `AXIOM_BPE_CKPT`) is never
   configured, the tokenizer is not fetched, and `init` then bootstraps the
   small offline kernel and reports *that* as the model. A fresh user who runs
   `axiom bench` right after `init` is benchmarking the legacy kernel, and on
   the 4-function sample in `new_user_simulation.sh` that shows **−49.1%
   token savings** (55 → 82 tokens): fingerprint overhead exceeds the input.
   The step still "passes" because the script only checks that a number was
   printed. (Known caveat in the commit that pointed `init` at the multilang
   checkpoint; this test confirms it is user-visible.) Recommendation: have
   `init` fetch `axiom_bpe.json` + `.meta.json` next to the checkpoint and
   write the three production settings into `~/.axiom/config.toml`; make
   `bench` say plainly when the input is too small for savings to mean
   anything (done in this change set: a caveat line below ~500 tokens).
2. **Memory recall is exact-match only without the contrastive embedder.**
   `axiom_recall`/`search` fall back to pooled TTT hidden states when
   `axiom_embedder.bin` is absent; a just-stored sentence is found by its
   exact text (1.00) but not by "max_tokens clamp ceiling" or "cargo fmt". The
   embedder is published nowhere (not on either Hub repo, not in the release
   assets). Recommendation: publish `axiom_embedder.bin` alongside the
   checkpoint (and have `init` fetch it), or lower the fallback's `min_score`
   and label fallback results as low-confidence.
3. **Drift gate.** The default threshold 7.03 is comfortable for optimfix
   (clean 5.4–5.9 vs garbage 8.9) but sits *on top of* the baseline
   checkpoint's clean range (6.8–7.5 vs 9.0), so the preserved baseline flags
   clean code. After a session has absorbed a codebase, an unrelated clean
   snippet scores 8.6 against the adapted state and is flagged — that is the
   documented semantics ("drift against the current fast weights"), but
   `evaluate_drift` returns `isError: true` both for `drift=YES` and for
   `drift=UNAVAILABLE` (no master vibe yet), which an MCP host renders as a
   tool failure. Recommendation: ship a per-checkpoint gate value in the
   sidecar or on the Hub, and reserve `isError` for actual failures.
4. **Published `v0.4.1` sidecar carries a CI-runner absolute path** in its
   `tokenizer` field (`/home/runner/work/…/axiom_bpe.json`). Harmless today
   (the engine takes the tokenizer from `AXIOM_TOKENIZER`), misleading for
   anyone reading the file; the multilang sidecar has the relative name.
5. **Local generation is not usable output.** `/v1/completions` on the
   optimfix model produces `{ { {` noise; that is expected for an 8.6 MB
   compression model, but the OpenAI-compatible generation routes advertise
   more than they deliver without a backend (`AXIOM_BACKEND`). Documented in
   `docs/BACKENDS.md`; worth a one-line banner on the route.

Everything in the hardening table behaved as specified, and the tolerant
checkpoint loader from #222 is what makes the two older Hub checkpoints
loadable at all.

## Reproduce

```bash
cargo build --release --locked --bin axiom           # in axiom_engine_rs/
# fetch the Hub files into a scratch dir, then:
AXIOM_PRODUCTION_BPE=1 AXIOM_TOKENIZER=<dir>/axiom_bpe.json \
AXIOM_BPE_CKPT=<dir>/axiom_production_bpe.bin \
  axiom_engine_rs/target/release/axiom bench axiom_engine_rs/src
./scripts/new_user_simulation.sh
./scripts/demo_end_to_end.sh
./scripts/smoke_compression.sh                       # mock upstream
```
