# The Proof Loop

AXIOM makes broad claims. The proof loop is the discipline that keeps them
honest: **three headline numbers, each with the exact command that reproduces
it, regenerated every release and tracked between releases in CI.**

If a number isn't in this loop, it isn't a claim the project stands behind — it
is research (see [`UPGRADES.md`](UPGRADES.md)) or experimental (see
[`EXPERIMENTAL.md`](EXPERIMENTAL.md)).

---

## The three metrics

### 1. Autonomous repair — the spearhead

**What:** fraction of seeded broken-repo fixtures the real
localize → deterministic Poly-JIT repair → verify loop drives to green,
end-to-end, reversibly. Deterministic; no LLM or network.

**Command:**
```bash
cargo run --release --bin axiom -- eval-agentic
```
**Read as:** `score: N/N` — a pass/fail capability gate, not yet a rate (the
built-in set is small; see [`BENCH-REPAIR.md`](BENCH-REPAIR.md) for the plan to
grow it into a held-out benchmark with a baseline comparison). The command
exits non-zero if any fixture regresses, so CI enforces it
(`.github/workflows/eval.yml`).

### 2. Context compression at fixed fidelity

**What:** token reduction over a real code tree, together with the structural
signature round-trip fidelity that must stay at 100% for the reduction to be
lossless in the ways that matter.

**Command:**
```bash
cargo run --release --bin axiom -- bench axiom_engine_rs/src
```
**Read as:** `<savings>% token savings (<before> → <after>) with <k>/<k> = 100%
signature round-trip`. The percentage is **tokenizer-dependent** — cite it with
`AXIOM_PRODUCTION_BPE=0` (legacy 256-vocab) or `=1` (production BPE, vocab
8000). Round-trip fidelity is model-independent and must be 100%.

**Cost, real traffic:** the whole-system dollar/quota figure
(`1 − axiom_cost_usd_total / axiom_cost_uncached_usd_total` from `/metrics` over
a real session) is reported per measurement in `bench/cvm/*RESULTS*.md`. It is
**not** regenerated by `proof_loop.sh` (needs live upstream traffic); the loop
carries the most recent measured value and its date.

### 3. Grounding / trust gate

**What:** the calibrated conformal grounding gate's coverage of genuinely
supported claims, plus the neural contradiction catch-rate.

**Command:**
```bash
cargo run --release --features tools --bin axiombench      # `trust` pillar
```
**Read as:** `<coverage>% supported-claim coverage; contradiction catch-rate
<lo>% → <hi>% (threshold <τ>)` over the calibration set in
`bench/trust/claims.jsonl`.

## The release ritual

Before tagging `vX.Y.Z`:

1. `./scripts/proof_loop.sh` — regenerates metrics 1–3 and prints a markdown
   table (writes `bench/results/proof-loop-<date>.md`).
2. If a number moved, understand why. A regression blocks the release unless
   it's a deliberate, documented trade-off.
3. Paste the table into:
   - the GitHub release notes,
   - the README *Proof Loop* section,
   - the *Current values* table above (append a row; keep history).
4. Tag. `release.yml` publishes binaries + checkpoint; `docker.yml` publishes
   the image.

Between releases, `.github/workflows/proof-loop.yml` runs `proof_loop.sh` on
every push to `main` and uploads the table as a build artifact, so drift is
visible without waiting for a tag.
