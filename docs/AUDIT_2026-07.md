# AXIOM-AETHER — Full Codebase Audit (2026-07-24)

Scope: entire repository at branch tip (engine `v0.4.1`, workspace HEAD
`dc6d41a`). Every "works" / "broken" claim below was reproduced in a clean
Linux CPU environment with the toolchain the project targets
(`cargo 1.94.1`, `rustc 1.94.1`). Commands and measured numbers are inline so
findings are reproducible, not asserted.

## TL;DR

The core product is **real and healthy**: the Rust engine builds clean, the
whole test suite is green, the library passes the deny-warnings clippy gate, and
the headline local features (compression, autonomous repair, grounding, doctor)
do what the README says. The problems are at the edges — one **broken release
surface (Docker)** and several **coverage / consistency gaps** — not in the core.

## What Works (verified this run)

- **Build.** `cargo build --release --locked` in `axiom_engine_rs/` compiles the
  engine plus the `axiom_core` mesh dependency cleanly in 3m46s.
- **Tests.** `cargo test --release --locked` → **688 passed / 0 failed / 1
  ignored** across 39 test binaries. The single ignored test
  (`semantic_harness.rs`) is deliberately gated (needs checkpoints + minutes of
  training); a second ignored path (`cvm_eval.rs`) spends real API credits and is
  opt-in by design.
- **Lint.** `cargo clippy --lib --locked -- -D warnings` is clean — the shipped
  library carries zero warnings.
- **Doctor.** `axiom --mode doctor` correctly detects CPU-only host and
  recommends devices.
- **Compression (headline).** `axiom bench axiom_engine_rs/src` →
  **82.4% token savings** (172,361 → 30,411 tokens), **99.9% round-trip**
  (2,174/2,176 signatures). Runs with no checkpoint, as documented. Matches the
  README's ~81.7% claim.
- **Autonomous repair (headline).** `axiom eval-agentic` → **9/9 fixtures PASS**,
  deterministic, no LLM. Real source-repair + rollback across shell/Rust/Python/
  JS/Go fixtures.
- **Mesh routing integration.** `axiom_core::mesh::KineticNeuralMesh` is genuinely
  wired into `swarm_router` → `routes_messages` via `server/run.rs`; opt-in behind
  `AXIOM_MESH_ROUTING=1` (+ `AXIOM_SWARM_LOCAL`). Not dead code.
- **Honesty labeling.** The experimental predictive tools emit `trained: false`
  and an explicit `state_source` (`predictive_tools.rs:185`), so callers can't
  mistake scaffolding for a calibrated model — this matches the README's caveats.

## What Is Broken

### 🔴 HIGH — Docker image build has been failing since the mesh integration

`docker.yml` (which builds/pushes the GHCR image advertised in the README's
Docker and Kubernetes sections) has failed on **every push to `main` since
2026-07-19**, commit #138 *"integrate Axiom Mesh into axiom_engine_rs's
local-SLM routing."* That commit added a path dependency:

```toml
# axiom_engine_rs/Cargo.toml:126
axiom_core = { path = "../axiom_mesh_rs/axiom_core" }
```

…but the `Dockerfile` only copied `axiom_engine_rs/` into the build context, so
`cargo build --locked` can't resolve the sibling crate. Reproduced exactly in a
Docker-shaped context:

```
error: failed to get `axiom_core` as a dependency of package `axiom_engine v0.4.1`
  failed to load source for dependency `axiom_core`
  Unable to update /build/axiom_mesh_rs/axiom_core
```

Impact: the published `ghcr.io/fernandogarzaaa/axiom-aether:latest` image is
stale (last good build 2026-07-19 10:19), and the README's `docker run …` and
Helm quick-starts install a version that predates the mesh work. The Docker CI
badge in the README is red.

**Fixed in this change:** the `Dockerfile` now also copies `axiom_mesh_rs/`
before building (the whole workspace is required because `axiom_core` inherits
from the `axiom_mesh_rs` workspace manifest). Verified: with both directories
present, `cargo metadata --locked` resolves; with only `axiom_engine_rs/` it
fails with the error above.

## What Needs Improvement

### 🟡 CI coverage gaps

- **Mesh workspace was untested in CI.** `axiom_prime` and `axiom_mcp` (~3.3k LOC,
  with a `stdio_transport` integration test and proptest suites) were never built
  or tested by `ci.yml`; only `axiom_core` was compiled transitively as an engine
  dependency, and its own unit/proptest tests never ran. **Addressed in this
  change:** `ci.yml` now runs `cargo test --release --locked` in `axiom_mesh_rs/`
  (verified locally: 15 passed / 0 failed).
- **Docker build is only exercised on `main`/tags**, so this class of breakage
  isn't caught until after merge. Consider a lightweight `docker build` (no push)
  on PRs, or at least building the image in `ci.yml`.

### 🟡 Two parallel "engines" with divergent maintenance

- `axiom_engine/` is a **Python/FastAPI reference implementation** (`server.py`,
  `ttt_layer.py`, `inference.py`, `response_cache.py`) with its own test suite
  (`tests/test_*.py`, `tests/_smoke_*.py`). **None of it runs in CI** — the only
  CI job is the Rust build. These tests can rot silently.
- Packaging is genuinely confusing: root `pyproject.toml` publishes the Python
  package as **`axiom-engine` v1.0.0**, while `pip install axiom-aether` ships the
  **Rust** binary wheel (`axiom_engine_rs`, v0.4.1). The README calls this out,
  but the version skew (1.0.0 Python vs 0.4.1 Rust for "the same" project) and the
  near-identical names are a footgun. Recommend either wiring the Python suite
  into CI or clearly marking `axiom_engine/` as a frozen/legacy reference.

### 🟡 Security posture for non-local deployments

- The default server bind is **`0.0.0.0`** (`entrypoint.rs:170`,
  `AXIOM_HOST` default), not loopback — appropriate for the Docker/Helm story but
  worth flagging.
- Only the `/mcp` transport has (optional) bearer auth via `AXIOM_MCP_TOKEN`
  (`routes_tools.rs`). The data-plane endpoints (`/v1/messages`, `/v1/adapt`,
  `/v1/sessions`, `/v1/config`, hypervisor routes, …) are **unauthenticated**.
  This is fine for the documented local-first use, but the Helm chart exposes a
  Service, and the README's `docker run -p 3000:8080` reaches an open control
  plane. Consider an opt-in API-key layer for the data plane, or make the docs
  explicit that these must sit behind a trusted network boundary.

### 🟢 Minor

- Compression round-trip is 99.9%, not 100%: **2 of 2,176 signatures** failed to
  expand byte-exactly on the engine's own source. Worth a look at which symbol
  shapes drop.
- `docker.yml` (and other workflows) still run several actions on the deprecated
  Node 20 runner — non-blocking, but will eventually break.

## What Is *Not* Wired (by design — not defects)

These are correctly gated/opt-in and behave as documented; listed so the map is
complete:

- **Predictive-reasoning tools** (`axiom_predict_states`, `_sample_trajectories`,
  `_align_generation`): reachable but the state-prediction head is **untrained**;
  responses self-report `trained: false`. Scaffolding, labeled as such.
- **Mesh / local-SLM routing**: off unless `AXIOM_MESH_ROUTING=1` +
  `AXIOM_SWARM_LOCAL`/`AXIOM_LOCAL_SLM` and a reachable Ollama-style backend.
- **CVM `haiku` digest, keepalive, DWE fleet listener, router consensus**: all
  opt-in via env, off by default, and documented.
